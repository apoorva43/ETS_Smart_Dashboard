PISA Smart Dashboard

Developer documentation & handoff guide — ETS Capstone 2025

Quick start:   make setup && make all-data && make run — then open http://localhost:8501.

Overview

The PISA Smart Dashboard is a Streamlit web application that visualises full student score distributions from the 2015, 2018, and 2022 PISA cycles across 81 countries. Rather than reporting country averages, it surfaces the distribution broken down by percentile, socioeconomic background, immigration status, school type, and location.

Two modes are available:

  • 📖 Data Story — a guided four-chapter narrative for policymakers (OECD standing → trends → equity gaps → school context), with auto-generated key findings and policy notes.
  • 🔍 Explore — a free-form analyst view with side-by-side comparison, intersectional heatmap, and country scatterplot.

The backend uses DuckDB + Parquet to push filters and aggregations to the data layer, so individual chart queries load only the columns and rows they need rather than the full 1.7-million-row dataset.

Setup

Prerequisites

  • Conda (Miniforge / Anaconda)
  • Make
  • ~15 GB free disk space for raw data + processed Parquet files
  • Internet access for the initial OECD data download

1 — Clone and create the environment

git clone https://github.com/your-org/pisa-dashboard.git
cd pisa-dashboard
make setup

This runs conda env create -f environment.yml and pip install -e .. Then activate:

conda activate ets_capstone

2 — Build the full data pipeline

make all-data

This runs all 7 pipeline steps end-to-end. See the Pipeline steps section for details on what each step does and how long it takes.

⚠️ Time estimate: Steps 1–3 download ~3 GB from the OECD and take 20–40 minutes. Steps 6–7 are CPU-intensive and take ~10–15 minutes each on a laptop.

3 — Run the app

make run
# or directly:
PYTHONPATH=. streamlit run app.py

The app opens at http://localhost:8501.

Running the app

On startup, app.py calls get_meta(), get_precomputed(), and get_se_lookup(). Each is decorated with @st.cache_data(ttl=3600) and tries the local data/processed/ path first, falling back to S3 if the file is not present locally.

All chart data is fetched on demand via the fetch(countries, year, cols) cached wrapper, which calls query_pisa() in src/data_loader.py. Cache keys are tuples (not lists) to ensure hashability.

Cache tip: If you update a processed Parquet file and the app shows stale data, click the hamburger menu → Clear cache and hard-refresh the browser.

# Download only 2022 school data
python src/build_data.py download --year 2022 --dataset school

# Rebuild precomputed file with a custom output path
python src/build_data.py precompute --out-path data/processed/pisa_precomputed_v2.parquet

Backend architecture

Query pattern

Every chart calls the cached fetch(countries, year, cols) wrapper in app.py, which delegates to query_pisa() in src/data_loader.py. DuckDB reads only the requested columns and rows from pisa_all.parquet — no full dataset is loaded into memory. 

# Example: fetch maths PVs + weight for Canada in 2022
pv_cols = tuple(f"PV{i}MATH" for i in range(1, 11))
df = fetch(("CAN",), 2022, ("CNT", "YEAR", "W_FSTUWT") + pv_cols)

Cache hierarchy

Three layers of caching reduce repeated computation:

  1. Streamlit @st.cache_data — in-memory cache of DataFrames, keyed by (countries, year, cols) tuples. TTL = 1 hour.
  2. persist="disk" — survives app restarts on Posit Cloud.
  3. Precomputed Parquet files — KDE arrays and SE stats are computed once at build time; the app does zero KDE fitting or BRR computation at render time.

S3 fallback

get_meta(), get_precomputed(), and get_se_lookup() each try the local data/processed/ path first. If the file does not exist (e.g. on a fresh Posit deployment), they fall back to: 

S3_BASE = "https://pisa-dashboard-data.s3.ca-central-1.amazonaws.com"

When you update any processed file, upload it to the S3 bucket root so deployed instances pick it up automatically.

Frontend architecture

App routing

app.py uses a sidebar radio to switch between Data Story and Explore modes. The Data Story calls render_story_tab(); Explore calls render_chart() for single-panel or the if side_by_side: block for two-panel views.

Chart rendering flow

render_chart(chart_type, ...)
  └── fetch(countries, year, cols)          # DuckDB query, cached
  └── plot_*() function                    # Returns go.Figure
  └── render_plotly_chart_with_note(fig)   # st.plotly_chart + info + caption

Precomputed vs runtime paths

Every chart that supports precomputed data has two code paths. When df_pre is not None (always true in production), the _precomputed variant of the plotting function is called. The raw-data fallback exists for local development without the precomputed file. 

fig = plot_country_shaded_density_precomputed(df_pre, subject, countries, year)
# vs fallback:
fig = plot_country_shaded_density(df, subject, countries, year)

Statistical methods

Plausible values

PISA does not report a single test score per student. Each student has 10 plausible values per subject (e.g. PV1MATH–PV10MATH) — multiple imputations from the posterior of their latent ability. All score statistics (means, percentiles, SEs) are computed by averaging across all 10 PVs per the PISA technical standards. No chart uses a single PV as a point estimate.

Sampling weights

W_FSTUWT is the final student sampling weight. It must be applied to all estimates so results generalise to the national population. Country sample sizes vary substantially — Canada: ~23,000 students; USA: ~4,500 — making correct weight application essential, not optional.

Standard errors — Fay BRR

Standard errors follow the Fay Balanced Repeated Replication method using 80 replicate weights (W_FSTURWT1–W_FSTURWT80). Total variance combines:

  • Sampling variance from the 80 BRR replicates
  • Imputation variance across the 10 plausible values

These are pre-computed in Step 7 and stored in pisa_se_stats.parquet, indexed by (CNT, YEAR, SUBJECT) for O(1) lookup at render time. A SE warning card appears in the UI only when SE > 3.5 points.

Data suppression

Subgroup breakdowns are suppressed when the underlying cell has fewer than 30 valid observations. The threshold is set in check_group_sizes() in app.py and _check_sufficient_data() in plotting_plotly.py (min_n=100 for the full figure, 30 per group).

OECD average computation

The OECD average is computed as the mean of country-level means — one value per member country, equally weighted — following the OECD's official methodology. Non-member partner economies are excluded from this average.

Adding a new PISA cycle

  1. Add the download URLs to PISA_URLS and PISA_SCHOOL_URLS in src/data_loader.py: 
    PISA_URLS = {
    2015: "https://...",
    2018: "https://...",
    2022: "https://...",
    2025: "https://..."   # ← add new cycle here
}
  2. Add the year to YEARS in the Makefile: 
    YEARS = 2022 2018 2015 2025
  3. Run the full pipeline: 
    make data precompute se
  4. Upload the four updated Parquet files in data/processed/ to S3.
  5. Check that the new year's column names match the existing schema. OECD occasionally renames questionnaire variables between cycles — search for year-specific column handling in src/data_loader.py and add any renames needed.

Adding a new chart type

  1. Write the Plotly figure function in src/plotting_plotly.py. Always use _base_layout() and return a go.Figure: 
    def plot_my_chart(df, subject, cnt, year=None) -> go.Figure:
    fig = go.Figure()
    # ... build traces ...
    fig.update_layout(**_base_layout(title=f"My Chart | {SUBJECTS[subject]}"))
    return fig
  2. Add the name to CHART_TYPES in app.py: 
    CHART_TYPES = [
    "Percentile score profile",
    "Score change over time",
    "Intersectional Heatmap",
    "Group comparison",
    "Country Scatterplot",
    "My New Chart",   # ← add here
]
  3. Add a branch inside render_chart() in app.py: 
    elif chart_type == "My New Chart":
    df = fetch(tuple(selected_countries), selected_year,
               tuple(BASE_COLS + pv_cols))
    fig = plot_my_chart(df, subject, primary_country, year=selected_year)
    render_plotly_chart_with_note(
        fig,
        note=get_chart_note("My New Chart"),
        key=f"my_chart_{widget_key}_{subject}_{selected_year}",
    )
  4. Optionally add a get_chart_note() entry and a CHART_HELP_TEXT entry for the collapsible help expander.

Adding a new equity group breakdown

  1. Add the variable mapping to GROUP_OPTIONS in src/config.py: 
    GROUP_OPTIONS = {
    ...
    "Grade repetition": ("REPEAT", {0.0: "Never repeated", 1.0: "Repeated at least once"}),
}
  2. Add a sort rank for the new group labels to _get_oecd_rank() inside both plot_group_shaded_density() and plot_group_shaded_density_precomputed() in src/plotting_plotly.py.
  3. Add the column to the column set fetched in render_chart()'s Group comparison branch in app.py if it is not already included in EQUITY_COLS.
  4. Re-run make precompute so the new group's KDE and percentile data is included in pisa_precomputed.parquet.
The GROUP_OPTIONS dict in config.py is the single source of truth for which breakdowns appear in the Explore tab's Group comparison selectbox. Adding an entry there is all that's needed for the UI to pick it up.

Deployment — Posit Cloud + S3

Posit Cloud

The app is connected to this GitHub repo and auto-deploys on push to main. Dependencies are read from requirements.txt (not the conda environment). Trigger a manual redeploy from the Posit Cloud dashboard if needed.

S3 bucket

Bucket: pisa-dashboard-data.s3.ca-central-1.amazonaws.com

When any processed Parquet file changes, upload it to the bucket root:

aws s3 cp data/processed/pisa_precomputed.parquet \
    s3://pisa-dashboard-data/pisa_precomputed.parquet

aws s3 cp data/processed/pisa_se_stats.parquet \
    s3://pisa-dashboard-data/pisa_se_stats.parquet

aws s3 cp data/processed/pisa_country_stats.parquet \
    s3://pisa-dashboard-data/pisa_country_stats.parquet

Posit Cloud memory constraints

Posit Cloud's free tier has ~1 GB RAM. The dashboard avoids loading the full dataset by querying only necessary columns via DuckDB. If you hit memory limits after adding new chart types, check that fetch() is called with a minimal cols tuple rather than BASE_COLS + PV_ALL + EQUITY_COLS.

Troubleshooting

SymptomLikely causeFix
App shows stale chart data after pipeline re-run Streamlit in-memory cache Hamburger menu → Clear cache → hard refresh
KeyError: (CNT, YEAR, SUBJECT) in SE lookup Country/year combo missing from pisa_se_stats.parquet Re-run make se; check that the country has ≥30 records with all 80 replicate weights
Immigration hover text not showing GROUP_LABEL values don't match keys in IMMIG_DEFINITIONS Print rows["GROUP_LABEL"].unique() and add matching substrings to the dict
Side-by-side time charts have mismatched y-axes Figures built independently with auto-range Ensure the both_time block in app.py pre-builds both figures and calls fig_.update_layout(yaxis=dict(range=[y_min, y_max])) before rendering
Legend floats to top of time chart in side-by-side view apply_compact_plotly_layout() overrides legend to y=1.08 Do not call apply_compact_plotly_layout() for time-change charts; _base_layout() already sets the correct y=-0.25
S3 latency ~4s on cold start S3 fallback triggered because local Parquet files absent Ensure processed files are present in data/processed/ on Posit, or pre-warm the cache
Percentile labels overlapping in density chart All five labels at the same y Stagger P25/P75 labels with y_center - 0.75 vs P10/Median/P90 at y_center - 0.55 using fig.add_annotation()
